## Build on the local machine

Use a Python environment with CairoSVG, Matplotlib, NumPy, SciPy, and Pillow.
For visual verification also install PyMuPDF.
CairoSVG needs the platform's Cairo library; consistent typography requires DejaVu Sans and DejaVu Sans Mono.
All archived image inputs are in this paper repository, so ordinary composition does not require PyBullet or the experiment checkout.
Run from the paper repository root:

```bash
python scripts/build_figures.py --overview
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
python scripts/verify_overview_figures.py
```

The first command rebuilds only Figures 1-3 as PDF, SVG, and PNG, and writes `data/overview-figure-build-manifest.json` with input/output hashes.
The layouts are 528 units wide; SVG labels and arrows remain vectors, while simulator scenes are embedded raster images.
The script emits PNG previews at twice the layout resolution and vector PDF exports for LaTeX.
Figma can import the SVGs for review, but edits in Figma are not automatically synchronized back to the generator.
Do not export the old Figma frames over these updated figures.

## Re-render locally without changing the experiment

Copy the selected run directories, their exact runtime/configuration, and the relevant assets to the local machine.
Preserve `info.log`, `scorecard.json`, level `index.jsonl`, primitive `actions.jsonl`, and any recording/state files required by that runtime.
Use the run's original flags from `info.log`, including seed, fresh-instance behavior, and task variants.
The experiment repository's `predicators/run/continual_video.py` provides the recorded-action replay path (`read_level_episodes`, `iter_level_frames`) and `scripts/continual_video.py` reconstructs the launch configuration.
Neither the paper compositor nor the trajectory importer currently automates a new GUI-render capture.
A local capture driver must select the archived events above from that replay, or restore complete saved simulator states when available.

Do not merely reset object poses in the current environment implementation.
Hidden state matters: Bridge has glue/contact history and attachment constraints, and Balloons has active attachments and motion state.
Verify replayed positions, attachment structure, selected event step, and terminal outcome against the original recording before calling a re-render an execution frame.
Camera, lighting, antialiasing, resolution, and purely visual materials may change; actions, geometry, object poses, hidden dynamics, and task outcomes must not.
Rendering must not advance physics.
Keep a fixed camera within each trajectory so movement between frames is interpretable.
Save a provenance note with the runtime commit, renderer/backend, view and projection matrices, resolution, source event, and replay checks.
If exact replay cannot be verified, retain the original frame or clearly label the alternative as an illustration.

Save improved images under `figures/sources/local_gui/` and add `data/figure-render-overrides.json`.
Keys may be the explicit gallery keys above or semantic source names such as `trajectory_bridge_0` through `trajectory_bridge_4` and `trajectory_balloons_0` through `trajectory_balloons_4`.
An explicit gallery key takes precedence over a semantic name.
Example:

```json
{
  "281:107:18": {
    "path": "figures/sources/local_gui/domino_initial.png"
  },
  "trajectory_bridge_3": {
    "path": "figures/sources/local_gui/bridge_step1702.png",
    "crop": [270, 280, 810, 860]
  }
}
```

Paths are relative to the paper repository.
Crop coordinates are pixels in the replacement image, not the original image; scale or recompute them if resolution changes.
Omit `crop` for an already composed/cropped panel; the compositor will fit it to the panel aspect ratio.
The replacement mechanism leaves archived evidence and its hashes unchanged and records replacement images in the overview build manifest.
Rebuild, inspect every domain mapping and all trajectory stages, and compile the paper before pushing to Overleaf.
